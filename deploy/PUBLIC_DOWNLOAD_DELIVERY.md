## 已实现的网页改动

- “视频图片提取”和“主页 / 合集”放到右侧标题下方，分别进入独立提取页面。
- 左侧和对应页面标题改为“网盘下载”。
- 下载选中和普通保存沿用浏览器下载流程。
- 支持 File System Access 的电脑浏览器可以选择一个 32 MiB 以上文件，点击“分段保存”。
  选择本地保存位置后，最多四路读取，每个分段 1 MiB，直接写入文件，不累计整个 GB 级 Blob。
  页面显示实际接收字节、速度与进度。分段重试最多三次，校验原文件 ETag、Content-Range、总大小。
  请求响应等待上限 30 秒，分段读取无进展上限 90 秒。
  磁盘写入失败、版本变化或主动取消均中止临时写入，不提交不完整文件。
- 分段保存需要保持页面打开；普通浏览器下载仍可以在刷新页面后继续。
- iPhone 相册流程和微信浏览器提示保留；分段保存没有改视频编码或压缩图片。

## 必须改变的分发线路

要显著加快公网下载，原文件必须从拥有足够出口带宽的服务器或文件存储发出。
仅把网页或一个代理搬到服务器，文件仍实时从家里电脑经过低速线路读取，不会消除源端瓶颈。

### 方案 A：下载器和原文件一起部署在服务器

1. 使用当前程序支持的系统环境部署下载器、下载工具及浏览器。
   现有本机授权采用 Windows 加密，不能承诺把密文复制到另一台机器即可继续使用。
   迁移账号时应在目标设备上进行官方连接，不能把管理员 Cookie 发给访客。
2. 原文件由服务器抓取和保存，用正式 HTTPS 域名直接分发，不再经过 Funnel。
3. 按并发人数配置出口：100 Mbps 理论合计约 11.9 MiB/s；五人同时传输要分享总带宽。
   应核对实际持续带宽、流量配额和用户所在地区线路，不能把标称端口速率当实测速度。
4. 国内与国外平台分别实测；服务器机房 IP 可能触发平台验证，不能保证换服务器后所有平台无需重测。
5. 保留访客任务所有权校验、下载记录七天、管理员接口隔离、Range 支持。

### 方案 B：本机解析，完整原文件同步到私有存储后分发

1. 下载完成后，将完整原文件传入有足够出口带宽的私有存储。
2. 验证对象大小和完整性，再为所属访客签发短时下载 URL。
3. 存储不公开；原文件 URL 不能跨访客使用。签名过期时重新校验访问权限。
4. 朋友直接从存储接收文件。首次同步仍受这台电脑上传带宽限制，不能隐藏这段等待。
5. 不降画质、不转码，不把大文件塞入浏览器内存。

方案 B 的代码已在 `relay-delivery` 分支实现（国内中转服务器 `relay/`、家里电脑 `web/relay_sync.py`、
网页签名链接与回退），部署步骤见 `relay/README.md`。未配置时功能完全关闭。

这两种方案尚未部署。本轮没有购买服务、创建外部存储、迁移授权或修改系统网络。
需要实际服务器或存储的配置和授权后才能实施、测量朋友端速度。
