局域网视频下载器
================

家里人在同一个路由器/WiFi 下，用浏览器打开一个链接就能下载视频，
不用装任何软件，手机也能用。

第一次打开：创建管理员账号
--------------------------
浏览器打开地址后会看到「首次使用」页面，设一个用户名和密码，这就是管理员账号。

**请你自己第一个打开并设置好**——在设置完成之前，局域网内任何人打开都能成为管理员。
设置完这个入口就自动关闭了。

之后点右上角「账号管理」给家里人开子账号：填用户名和密码，点添加，
把这两样告诉他就行。

账号是怎么隔离的
----------------
- 每个人只能看到自己提交的下载记录，看不到别人的
- 只能删自己的记录，删不了别人的
- 也下载不了别人的文件（直接访问链接会提示不存在）
- 管理员能看到所有人的记录，别人的会标出是谁提交的

管理员还可以给任何账号重置密码、删除账号。
重置密码后那个人会被强制退出，需要用新密码重新登录。

登录状态保持 30 天，期间不用反复输密码。

注意：局域网走的是 HTTP 不是 HTTPS，登录密码在局域网内是明文传输的。
家里用没问题，但不要把这个端口暴露到公网。

怎么启动
--------
1. 双击「网页版下载器.cmd」
2. 窗口里会显示一个地址，形如  http://192.168.0.14:8000
3. 把这个地址发给家里人，他们浏览器打开就能用
4. 你自己也可以用 http://localhost:8000

这个窗口关掉，链接就失效了。要用就保持开着。

第一次使用：必须先放行防火墙
----------------------------
右键「Add-FirewallRule.ps1」->「使用 PowerShell 运行」，
如果提示需要管理员，就在管理员 PowerShell 里运行它。只需做一次。

不做这一步，只有你自己的电脑能打开，家里其他设备一律连不上——
这是局域网访问失败的头号原因。

规则只对"专用网络"生效（家里/公司 WiFi）。
拿到咖啡馆连公共 WiFi 时不会开放，不用担心被陌生人访问。

链接会变的情况
--------------
地址里的 IP 是路由器自动分配的，重启路由器或断网重连后可能变成别的。
一旦家里人打不开了，重新双击启动器看一眼新地址即可。

想让地址永远不变：进路由器后台，找「DHCP 静态地址分配」或「IP 与 MAC 绑定」，
把这台电脑固定到 192.168.0.14。设置一次，以后地址就不会再变。

其它注意事项
------------
- 你的电脑必须开着且不休眠，否则链接打不开。
  建议把电源设置里的"睡眠"改成"从不"。
- 家里人不需要配任何代理。去 TikTok 取视频这一步走的是你电脑的网络
  （包括你的代理），从你电脑传到他们手机那一步是纯局域网。
- 下载的文件存在 downloads 文件夹，按任务分子目录。
  点网页上的「删除」会连文件一起清掉。
- 同时最多下 2 个任务，避免把上行带宽和代理打满。
- 有的路由器的访客 WiFi 开了「AP 隔离」，设备之间互相不通。
  如果连不上，确认大家连的是同一个主 WiFi，不是访客网络。

技术说明
--------
后端 FastAPI + yt-dlp，前端单页无框架。

Symphony 引擎是 Get-SymphonyVideos.ps1 的 Python 移植，两个坑照旧：
只取 previewLink（否则一个视频下 5 遍），文件名带 vid 后缀（否则同名素材互相覆盖）。

画质排序 format_sort = res,fps,tbr。yt-dlp 默认把"编码格式新"排在码率前面，
在 TikTok 上会选中同样 720p 但码率只有三分之一的 H.265 流，看着发糊。

依赖里的 curl-cffi 是必须的。yt-dlp 的独立 exe 自带，pip 默认不装。
少了它 TikTok 直接报 "Unexpected response from webpage request"，
因为 TikTok 需要 TLS 指纹模拟才肯正常响应。重建环境时务必用 requirements.txt。

重建 Python 环境
----------------
  python -m venv .venv
  .venv\Scripts\python.exe -m pip install -r requirements.txt
